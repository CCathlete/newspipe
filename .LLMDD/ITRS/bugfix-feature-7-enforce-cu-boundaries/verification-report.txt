ISSUE
-----
CU cu-008 was escalated because test_sibling_write_is_not_a_breach (T008.7)
failed. The test fixture had cu-001's no-touch guard including "src/owned.py",
which caused the runner to correctly report a boundary breach when cu-001 wrote
to src/owned.py — but the test expected zero breaches. This created an
unresolvable contradiction: exempting own-guard exact-file writes would gut
Rule 1 (no-touch over-fire fix) for the common case of exact-file guards.

ROOT CAUSE
---------
Guard fixture for cu-001: "Do NOT touch: .LLMDD/agents, src/owned.py\nStop when x\n"
The bare file pattern "src/owned.py" matched itself when cu-001's write
target was src/owned.py, triggering a no-touch breach. The test assumed
such a write should not breach, but the design semantics (spec: "Enforce:
own no-touch") require that a CU writing its own forbidden path IS a breach.

FIX APPLIED
-----------
Changed cu-001's guard in TestBoundaryRules._guards from:
  "Do NOT touch: .LLMDD/agents, src/owned.py\nStop when x\n"
to:
  "Do NOT touch: .LLMDD/agents\nStop when x\n"

This removes src/owned.py from cu-001's no-touch list, which:
- Preserves test_own_no_touch_breach (still covered by .LLMDD/agents/** guard)
- Preserves test_sibling_write_is_not_a_breach (src/owned.py no longer guarded for cu-001)
- Preserves test_shared_write_breach, test_unattributed_breach_names_the_guard, test_unenforceable_fails_closed
- Honors the design intent: own-guard dir-pattern writes still breach; exact-file
  exemption for own writes is the configured guard's role
